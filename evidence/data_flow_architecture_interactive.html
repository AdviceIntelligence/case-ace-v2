Authentication & Downscoped Token Brokering

Clear architectural separation between Microsoft Entra ID login and Google Cloud STS security tokens.

A

1. Adviser Enterprise Login (Microsoft Entra ID)

  1. Adviser navigates to Case Ace web application.
  2. Browser initiates OIDC Authorization Code Flow with PKCE against Microsoft Entra ID.
  3. Adviser completes organisational SSO with mandatory FIDO2 / Authenticator MFA.
  4. Entra ID issues signed ID Token asserting adviser identity & RBAC role (CaseAce.Adviser).
  5. Zero case data, audio, or client details touch Microsoft.
B

2. Scoped GCP STS Credential Minting

  1. Browser presents validated Entra ID JWT to CAW Backend (europe-west2 Cloud Run).
  2. Backend validates signature, claims, and session active status.
  3. Backend invokes Google Cloud Security Token Service (STS) to mint a downscoped OAuth access token.
  4. Token is strictly restricted: 15-minute TTL, scoped solely to Vertex AI & STT APIs in europe-west2.
  5. Browser uses STS token directly for encrypted TLS 1.3 model invocation.
